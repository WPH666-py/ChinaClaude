settings: 一张选项卡 = 一个模型，四项内置，可保存可删除

上一版把「服务商」和「给它加第一个模型」拆成了两个步骤、两个位置（卡片 + 底下一张新增
表单），填完点保存什么也没发生 —— 保存按钮要三个字段都非空才亮，而亮不起来的按钮不会
解释原因。用户看到的结论就是"新建选项卡没有显示在前端"。这一版把结构拍平：

- 设置 → 模型 里只有并列的选项卡，每张内置 服务商 / 模型名称 / Base URL / API-KEY
  四项，各自带「保存」与「删除」。「+ 新建」直接追加一张空卡片，删掉底部那张新增表单。
- 编辑是草稿：输入只改本地 draft，点「保存」才写入 store；未保存的卡片打「未保存」标记，
  保存按钮在有改动时才高亮。
- 一项服务商只存一个模型，由 splitOneModelPerCard() 在加载时保证。旧数据里"一个服务商挂
  多个模型"被按模型拆开而不是丢弃，每个模型继承原端点与 Key。
- 新增 dropCardStubs()：既无模型、又无端点、又无名字的卡片加载时丢掉，否则「+ 新建」之后
  直接关掉设置会永久留下空记录。
- API-KEY 为空不阻止保存（首屏已会报「缺少 API-KEY」），模型名称与 Base URL 为空会阻止
  并说明缺哪一个。
- 「测试连接」结果带取值签名，只在仍描述当前字段时显示，避免把「连接正常」留在改过的
  URL 旁边。
- store：addModel/removeModel/setModelEffort 合并为 setProviderModel()（替换而非追加，
  保留模型 id 与已选推理挡位）；defaultModelOption() 在默认卡片尚未保存时回落到第一张
  可用卡片，空草稿不会让配好的应用显示成"未绑定模型"。

验证：vue-tsc --noEmit 与 vite build 均通过；用 _probe/shot-cdp.mjs 驱动真实点击验证了
旧数据拆成两张卡片、「+ 新建」+填字段后 未保存=1 且保存可用、点保存后落盘为
{name:"智谱 GLM"(按主机名推导), model:"glm-4.6"} 且 未保存=0、空列表显示引导文案。
